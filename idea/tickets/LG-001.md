# LG-001 — App shell and rules package

Phase 0 · Phone shell
Depends on: tech proposal accepted
Blocks: LG-002, LG-003

## Outcome

`app/` is a Flutter application. `packages/rules/` is a Dart package with no Flutter imports. The rules test command passes on the Windows workspace. A GitHub Actions workflow on `macos-latest` compiles an unsigned iOS build and uploads it as an artifact. No match logic yet. No Apple ID, certificate, or provisioning profile is stored in the repo or in Actions secrets.

The Pygame tree stays in `prototype/` and still runs with `py -3.13 main.py` from that folder.

## Acceptance

- `app/` and `packages/rules/` exist at the repo root, not under `idea/`.
- The iOS project exists under `app/`. Installing the artifact on the iPhone is LG-002. Android project files may exist because Flutter generates them; they are not run in this ticket.
- The rules package test command exits 0 on Windows.
- The workflow runs on demand and on the branch Phase 0 uses. It does not run on every commit, so macOS minutes stay limited.
- The artifact is an unsigned `.ipa` a Windows Sideloadly install can re-sign.
- The app requests no network permission.

## Out of scope

- Board rendering, rules, navigation, icons beyond the template, TestFlight, a paid Apple Developer account.
